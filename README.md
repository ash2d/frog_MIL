# frog_MIL

Hourly detection of two Andean frogs, *Gastrotheca chrysosticta* and
*Oreobates berdemenos*, in acoustic-monitor recordings, trained from **hourly
labels only**. Each hour is treated as a multiple-instance learning (MIL) bag
of 24 five-second windows. The pipeline is frozen
[Perch v2](https://github.com/google-research/perch-hoplite) embeddings, then a
small probe per window, then a pooling function that turns window scores into
one hourly score. The study compares five pooling functions: mean, max,
log-mean-exp, linear-softmax and attention.

## Result

The best model is a **linear probe with max pooling and an ordinal loss
(w = 2)**: macro AP 0.859 [0.784, 0.925] on 432 held-out hours (Feb–Apr and
Sep–Dec 2019). Only max at w = 1 and w = 0.25 is tied with it. Every LME,
mean, linear-softmax and attention model is significantly worse. Every trained
model beats the clock and Perch zero-shot baselines. The ordinal loss on the
0–3 calling index helps max (at w = 2) and linear-softmax but hurts attention.
The MLP probe and attention overfit the training hours. Validation is too small
to pick the pooler reliably, and its *Oreobates* hours are easier than test.
Details, and how these results differ from the earlier Sep–Dec-only run (v1,
archived in `*_previous_v1_sep-dec2019/`): [docs/findings.md](docs/findings.md).

## Setup

Requires [uv](https://docs.astral.sh/uv/) and a CUDA GPU for embedding.
TensorFlow (Perch) and torch ship conflicting CUDA stacks, so they get two
environments:

```bash
uv sync                                                         # .venv: torch, training, figures
UV_PROJECT_ENVIRONMENT=.venv-perch uv sync --only-group perch   # .venv-perch: TF + Perch
```

The labels are in `data/`. The audio (1 min WAV clips named
`HELECHOS_YYYYMMDD_HHMMSS.wav`) is not in the repo. Pass its directory with
`--audio-dir`.

**Adding audio:** put the new WAVs in the same folder, then rerun the pipeline
from `frog-manifest`. The embedding step embeds only the clips it hasn't seen.
The splits change, so every run has to be retrained. Archive the old `runs/`,
`results/` and `viz/figures/` first if you want to keep them.

## Pipeline

```bash
.venv/bin/python -m frog_mil.annotations --audio-dir <wav dir>   # label + audio coverage report
.venv/bin/frog-manifest --audio-dir <wav dir>                    # outputs/: bags, windows, splits
scripts/perch_env.sh python scripts/embed_perch.py               # embeddings/ (incremental: embeds only new clips)
.venv/bin/frog-train --seeds 5 [--hidden 256] [--ordinal-weight 0.5]   # 5 poolers × 5 seeds
.venv/bin/frog-report                                            # results/
.venv/bin/python viz/make_figures.py                             # viz/figures/
.venv/bin/python scripts/recall_at_precision.py                  # results/recall_at_precision.csv
.venv/bin/python scripts/split_ap.py                             # outputs/split_ap.csv: train/val/test AP per seed
```

Each `frog-train` call is one **run**, `{probe}-{target}-s2` (for example
`linear-ord0.5-s2`; `s2` = contiguous 5 s windows, the only geometry). It trains every pooler, which makes one **model** per
pooler: `{run_id}/{pooling}`. Predictions and checkpoints go to
`runs/<run_id>/<pooling>/`.

## Layout

```
data/        hourly labels
src/frog_mil/
  annotations.py  label + audio coverage report
  manifest.py     bags/windows CSVs; 3-day-block splits
  data.py         bag dataset over the cached embeddings
  pooling.py      the five pooling functions
  models.py       instance probe, ordinal head, MIL model
  train.py        train all poolers × seeds for one run; baselines
  evaluate.py     AP helpers and baselines
  report.py       paired-bootstrap tables -> results/
  audio.py        read raw windows for listening
scripts/     Perch embedding; recall-at-precision and per-split AP analyses
viz/         figure code and figures
results/     generated tables (tracked)
runs/ embeddings/ outputs/   generated, not tracked
*_previous_v1_sep-dec2019/   archived v1 (Sep–Dec audio only): results/, viz/figures/, runs/, ...
```
