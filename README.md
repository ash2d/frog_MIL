# frog_MIL

Hourly detection of two Andean frogs, *Gastrotheca chrysosticta* and
*Oreobates berdemenos*, in acoustic-monitor recordings, trained from **hourly
labels only**. Each hour is treated as a multiple-instance learning (MIL) bag
of five-second windows: 12, 24 or 36 per hour, depending on how many one-minute
clips the recorder made that hour. The pipeline is frozen [Perch v2](https://github.com/google-research/perch-hoplite)
embeddings, then a small probe per window, then a pooling function that turns
window scores into one hourly score. The study compares five pooling functions:
mean, max, log-mean-exp, linear-softmax and attention.

## Result

On 4914 hours, every one scored out of fold by 5-fold cross-validation over
3-day blocks, the validation-selected model (MLP-256 probe, log-mean-exp
pooling, ordinal loss w = 0.5) reaches **macro AP 0.856 [0.813, 0.887]**
(*G. chrysosticta* 0.837, *O. berdemenos* 0.875). The best baseline, a clock
of hour × month, reaches 0.445. **LME and mean pooling are tied at the top**:
14 models are within the CI, including every mean model. Max, linear-softmax
and most attention models are significantly worse, through *Oreobates*.
Mean is best for *Gastrotheca*, LME for *Oreobates*, and isolated calls are the
hard case for both (AP 0.33–0.56). **Caveat:** the recording regime is
confounded with the labels. *Gastrotheca* is positive in 23% of the 8 kHz
hours and ~4% of the 44.1 kHz ones. Within each regime AP stays far above chance,
but silent 8 kHz hours score high, and a band-limiting control is still to be
run. Details are in [docs/findings.md](docs/findings.md).

## Setup

Requires [uv](https://docs.astral.sh/uv/) and a CUDA GPU. TensorFlow (Perch) and
torch ship conflicting CUDA stacks, so they get two environments:

```bash
uv sync --group dev                                             # .venv: torch, training, figures, tests
UV_PROJECT_ENVIRONMENT=.venv-perch uv sync --only-group perch   # .venv-perch: TF + Perch
```

The labels are in `data/`. The audio (1 min WAV clips named
`HELECHOS_YYYYMMDD_HHMMSS.wav`) is not in the repo. Its folder and the store for
large artefacts (embeddings, trained runs) are set in
[`src/frog_mil/config.py`](src/frog_mil/config.py), overridable with
`FROG_AUDIO_DIR` and `FROG_STORE`.

## Pipeline

One command keeps everything up to date. Each stage is fingerprinted, so only
what changed is rerun:

```bash
.venv/bin/frog status              # which stages are stale, and why
.venv/bin/frog run --gpus 0,2      # manifest → embed → train (sweep.toml) → report → figures
.venv/bin/python -m pytest -q      # tests
```

| stage | does | stale when |
|---|---|---|
| `manifest` | QC every WAV, join to the labels, assign recording regimes and 5 cross-validation folds (`outputs/`) | labels, audio folder or manifest code changed |
| `embed` | Perch v2 embeddings of every 5 s window, incrementally (store `embeddings/`) | windows not all cached, or audio files replaced |
| `train:<run_id>` | one run per `[[run]]` in [`sweep.toml`](sweep.toml): 5 poolers × 5 seeds × 5 folds | missing, unfinished or different settings for this dataset |
| `report` | block-bootstrap tables → `results/` | models, manifest or report code changed |
| `figures` | → `viz/figures/` | same, for the figure code |

The manifest is hashed into a `dataset_id`; embeddings, runs (`runs/<dataset_id>/`),
tables and figures all record it and refuse to mix. When the dataset changes,
the old tables and figures are archived to `archive/<dataset_id>/`.

**Adding audio:** `scripts/ingest.py status` lists what's new on Dropbox,
`pull <batch>` stages it, `verify <batch>` checks hashes and audio QC, and
`merge <batch>` moves it into the audio folder without overwriting. Then
`frog run`.

Each run is `{probe}-{target}-s2` (for example `linear-ord0.5-s2`; `s2` =
contiguous 5 s windows). It trains every pooler, which makes one **model** per
pooler: `{run_id}/{pooling}`.

## Layout

```
data/            hourly labels
sweep.toml       the runs `frog run train` keeps up to date
src/frog_mil/
  config.py      paths and constants
  pipeline.py    the `frog` runner: stages, staleness, GPU scheduling
  annotations.py label + audio coverage report
  audio.py       WAV quality control; reading windows to listen to
  manifest.py    bags/windows CSVs; regimes; cross-validation folds; dataset_id
  embcache.py    the embedding cache (keyed by window id + file signature)
  data.py        all bags as one padded tensor; fold views
  pooling.py     the five pooling functions
  models.py      instance probe, ordinal head, MIL model
  train.py       train all poolers × seeds × folds for one run; baselines
  runs.py        the run store: configs, loading models and predictions
  evaluate.py    AP, per-index AP, baselines
  stats.py       block bootstrap shared by report and figures
  report.py      tables -> results/
scripts/         Perch embedding (TF env), CUDA wrapper, Dropbox ingest
tests/           pytest suite
viz/             figure code and figures
results/         generated tables (tracked)
archive/         tables and figures of earlier data versions (tracked)
outputs/         manifest, QC cache, logs, stamps (not tracked)
```
